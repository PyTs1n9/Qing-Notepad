# 决策记录：`main-web` 分支上的网页小工具「碎片墙」

> **TL;DR**
> - `web/` 是一个**零构建**静态站点：`index.html` + `styles.css` + `app.js` + `tidy.js`，没有打包器、没有依赖、没有安装步骤。发布时把站点根指到 `web/` 即可。
> - 分支只是承载形态转换，**不删除也不改动 Tauri 源码**：`src/`、`src-tauri/` 在 `main-web` 上原样保留，切换分支即可回到桌面版。
> - 数据存 `localStorage`（键 `qing-fragment-wall:v1`），不上传、不登录；不做 IndexedDB，因为单条碎片是纯文本，量级到不了 5 MB 配额。
> - 整理逻辑（`tidy.js`）是**纯函数**，不碰 DOM 与时钟，`tidy.test.js` 用 `node --test` 单测；界面由 `app.js` 渲染它返回的结果。
> - 视觉沿用 `src/index.css` 的 `.theme-dark` 调色板（`#1a1b1e` 底、`#5c7cfa` 强调、`#738df9` 强调文字），网页版与桌面版读起来是同一个产品。

---

## 0. 为什么需要这一层

WorkBuddy「1024 造物挑战」的投稿表单第 04 项是**单选，只有「网页应用 / 小程序应用」**，第 06 项要求「在 WorkBuddy 将作品发布为网站后复制公开链接」，并注明「上传未能正常体验的链接不作为有效体验链接」。青记是 Tauri 桌面应用：

| 障碍 | 事实 | 后果 |
| --- | --- | --- |
| 形态不符 | `src-tauri/` 提供窗口、托盘、全局快捷键 | 无法「发布为网站」 |
| 数据层短路 | `storage.ts:134` 在非 Tauri 环境直接 `return null`，`App.tsx` 的初始化链依赖 Rust 侧 `storage_get_root` | 直接部署 `dist/` 得到空壳，写入抛错 |
| 产物体积 | `dist/` 约 54 MB，其中 `models/` 本地向量模型 24 MB | 静态托管未必接收 |

## 1. 结论

在 `main-web` 分支新增 `web/`，只做一件事：**接住碎片 → 一键整理成待办清单**。它不试图复刻青记，也不与桌面版共享代码——共享的是设计语言与产品概念。

被主动放弃的能力（网页形态做不到或性价比太低）：

- 便签 / 磁贴的多窗口、置顶、托盘与全局快捷键（依赖 Tauri webview window）
- 知识图谱的目录扫描（依赖 Rust `vault_*` 命令族与 `fs:scope`）
- 本地向量检索（24 MB 模型 + ORT WASM，首屏成本不划算）
- 在线工作台的实时协作（需要 Supabase 与协作服务，评审打开就要能写）

## 2. 整理算法（`tidy.js`）

一条从碎片到清单的确定性流水线，无模型、无网络：

1. **拆句**：`。！？!?；;` 与换行硬拆；逗号仅在整句超过 24 字时拆，避免「买牛奶，顺便取快递」被切碎。终止问号保留——`要不要做置顶小窗？` 是疑问，去掉问号就成了命令。
2. **清洗**：去掉行首列表符、序号、`[ ]` 复选框语法。
3. **去重**：以「去空白 + 去标点 + 小写」为键，重复条目计入 `stats.dropped`。
4. **归类**：问句（`?` 结尾或疑问词开头）→ `待确认`；以行动动词（写 / 改 / 发 / 确认 / 部署…）开头或含时间词 → `待办清单`；长度 ≤ 12 且无动词 → `原样保留`。
5. **分组**：按首个 `#标签` 分组，`未分类` 排最后；组内按 行动项 → 待确认 → 原样 排序。

## 3. 验证方式

本机无 GUI，所以验证不靠肉眼：

- `npm test`（`node --test`）：10 条用例覆盖拆句、去重、标签、归类、时间词、空输入。
- `npm run smoke`：`serve.mjs` 起静态服务 → 无头 Chrome 走 CDP → 真点一遍「输入回车存下 → 一键整理 → 关闭抽屉 → 勾选完成 → 标签筛选 → 清空后的空状态」，17 条断言 + 4 张截图（桌面 / 抽屉 / 移动端 / 空状态）。
- 这套冒烟脚本零依赖（Node 22 自带 `WebSocket`），可用 `CHROME_PATH` 指定浏览器。
