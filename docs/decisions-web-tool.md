# 决策记录：`main-web` 分支上的网页版「青记」

> **TL;DR**
> - `web/` 是**零构建**静态站点：`index.html` + `styles.css` + `app.js`，文本逻辑在 `tidy.js`（碎片整理）与 `md.js`（Markdown 子集）两个纯函数模块里，可用 `node --test` 直接单测。发布时站点根指到 `web/` 即可。
> - 壳层**复刻桌面端几何**：36px 顶栏 + 单一 `border-b`，6px 留白承载三张浮卡（活动栏 48px + 资源管理器、编辑区、右侧面板），卡片圆角 10px，行高 26–30px，正文 12.5–13px，配色取 `src/index.css` 的 `.theme-dark`。
> - 两个面：**碎片墙**（接住零碎念头、一键整理成清单）与**笔记**（Markdown 编辑 / 预览 / 分屏、文件夹、全文搜索）。整理结果可一键「存为笔记」，这是两面之间唯一的桥。
> - 数据全部落 `localStorage`（`qing-fragment-wall:v1`、`qing-notes:v1`），免登录、不上传；分支不改动 `src/` 与 `src-tauri/`，桌面版在 `main` 上原样保留。
> - **分支定位已定：`main-web` 是第二产品线，长期保留，不与 `main` 互相合并。** 桌面端从 `main` 出包，网页版从 `main-web` 发布；两边共用的改动手动移植、各提交一次（见 `AGENTS.md` 的 Git 分支清单）。

---

## 0. 为什么需要这一层

WorkBuddy「1024 造物挑战」投稿表单第 04 项只有「网页应用 / 小程序应用」，第 06 项要求「发布为网站」后的公开链接，且注明「上传未能正常体验的链接不作为有效体验链接」。青记是 Tauri 桌面应用，三个硬障碍：

| 障碍 | 事实 | 后果 |
| --- | --- | --- |
| 形态不符 | 窗口、托盘、全局快捷键由 `src-tauri/` 提供 | 无法「发布为网站」 |
| 数据层短路 | `storage.ts:134` 在非 Tauri 环境返回 `null`，`App.tsx` 初始化依赖 Rust 侧 `storage_get_root` | 直接部署 `dist/` 得到空壳 |
| 产物体积 | `dist/` 约 54 MB（`models/` 本地向量模型 24 MB） | 静态托管未必接收 |

## 1. 结论与边界

网页版保留「与本体同构的壳」和两件最核心的事，其余能力明确不做：

- **不做**：便签 / 磁贴多窗口、托盘与全局快捷键、知识图谱目录扫描（依赖 Rust `vault_*` 与 `fs:scope`）、本地向量检索（24 MB 模型 + ORT WASM 首屏成本过高）、在线工作台（需 Supabase 与协作服务，且评审打开就要注册）。
- **做**：碎片墙 + 笔记面 + 右侧整理面板；三者共用一套资源管理器（标签 / 文件夹 / 笔记树）。

## 2. 壳层复刻清单

| 桌面端 | 网页版取值 |
| --- | --- |
| 顶栏 `h-9` + 单一 `border-b` | `--titlebar-h: 36px`，`border-bottom: 1px solid rgba(255,255,255,.06)` |
| 窗口留白 `pad/gutter/top-gap = 6` | `.shell { padding: 6px; gap: 6px }`，卡片圆角 `10px` |
| 活动栏 48px | `--rail-w: 48px`，激活项左侧 2px 强调条 |
| 三浮卡（左栏+资源管理器 / 编辑区 / AI 面板） | 左卡（rail + explorer） / 主卡 / 右卡（整理结果） |
| `.theme-dark` 调色板 | `#0b0c0e` 底、`#1a1b1e` 卡、`#2b2d33` 线、`#5c7cfa` 强调、`#738df9` 强调文字 |
| 树行 / 待办行 | 26–30px 行高、发丝线分隔、右侧 tabular 计数 |
| 标题栏中央 `Qing Notepad` 字标 | 同款 letter-spacing 字标，窄屏隐藏 |

右侧整理面板刻意做成**停靠的第三张卡**而非抽屉浮层：桌面端的右侧卡就是 AI 面板，同构之后整屏比例与本体一致。

## 3. 文本管线

**`tidy.js`（碎片 → 清单）**：拆句 → 清洗 → 去重 → 归类 → 按首个 `#标签` 分组 → Markdown。
终止问号必须保留，否则「要不要做置顶小窗？」会被读成命令；逗号只在整句超过 24 字时拆，避免「买牛奶，顺便取快递」被切碎。

**`md.js`（Markdown 子集）**：标题、段落、有序/无序/任务列表、围栏代码、引用、分隔线、行内加粗/斜体/代码/链接。
`src/utils/markdown.ts` 依赖 `marked` + `highlight.js` 共 633 行，零构建页面无法直接引入，因此自己解析并**返回数据而非 HTML**——DOM 由 `app.js` 逐节点构造，用户文本永不进 `innerHTML`；`javascript:` 链接在 `sanitizeHref` 里降级为纯文本。

## 4. 手机端

- 活动栏转成 40px 横条；宽度 ≤860px 时编辑区独占剩余高度。
- 笔记面二选一：`body[data-surface="notes"][data-note-mode="list|read"]` 决定显示资源管理器还是正文；返回键切回列表。
- 分屏在手机上退化为编辑器（两栏各 190px 无法阅读），完整预览由「预览」档提供。
- 右侧面板改为覆盖层。

## 5. 验证方式

本机无 GUI，验证不靠肉眼：

- `npm test`：19 条用例（`tidy.js` 10 条 + `md.js` 9 条）。
- `npm run smoke`：静态服务 → 无头 Chrome 走 CDP，31 条断言覆盖两个面的主流程，并输出 7 张截图（桌面墙 / 桌面整理面板 / 桌面笔记 / 手机墙 / 手机笔记 / 手机笔记列表 / 空状态）。
- 冒烟脚本零依赖（Node 22 自带 `WebSocket`），可用 `CHROME_PATH` 指定浏览器。

## 6. 未决问题

- 发布域名与 sharecode 归属：需在 WorkBuddy 侧执行「发布为网站」，站点根目录选 `web/`。
- 中英双语：桌面版有 i18n，网页版目前硬编码中文。
- 桌面端的便签、画布、知识图谱与在线工作台仍未进入网页版，是否需要第二步（登录 + 协作）取决于这条支线是否继续。
- 网页版独立版本号：目前跟随仓库 commit，没有自己的 `v*` 标签；若要单独发布节奏，需要另起标签前缀（如 `web-v0.1.0`），避免触发桌面端的 release workflow。
