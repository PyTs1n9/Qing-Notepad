# 决策记录：片段库插件（`qing.snippet`）

> 2026-10-28。由 `grill`（常规强度）逐轮收敛。上下文见 `plugin-guide.md`（API v1 全貌）与
> `decisions-plugin-system.md`（插件系统总取舍）。

## 起因

用户问「插件系统还能加什么小功能」。盘点 `apiVersion: 1` 的 13 个权限码后选定**片段库**：
它是唯一能把 `storage` + `views` + `editor:write` + `editor:selection` 串成一个闭环的点子，
因此同时充当「覆盖全部权限面的参考实现」——现有 `qing-outline` 只覆盖编辑器侧，
`qing-note-wordcount` 只覆盖 notes 侧。

## 结论

### D1 只做插入，不做「用片段新建笔记」

**结论**：片段的作用域限定为「把文本插入当前笔记」，不提供 `notes:create` 路径。
**理由**：插入已覆盖绝大多数场景；`notes:write` 会把授权弹窗从 5 条抬到 6 条，
用一条「能写我的笔记库」的重权限换一个边缘功能不划算。真要做笔记模板，应当是另一个插件，
它的权限故事才干净（只读片段 + 写笔记，不含编辑器写入）。

### D2 支持四个占位符，明确不支持 `${title}`

**结论**：插入时解析 `${date}`（`YYYY-MM-DD`）、`${time}`（`HH:mm`）、`${cursor}`（插入后光标落位）、
`${selection}`（有选区时用选区文本替换；无选区时塌成空串）。
**理由**：占位符是这个插件相对"复制粘贴"的唯一增量——不做就只剩剪贴板的功能子集。
`${title}` 做不了：`apiVersion: 1` 没有「当前打开的是哪篇笔记」这个调用
（`qing-note-wordcount` 的注释里已记录同一限制），拿不到笔记标题。
未识别的 `${...}` **保留字面量**，故意不替换成空串——用户看到 `${title}` 还在，就知道它没被支持。

### D3 管理入口：两级侧栏树 + 六条命令

**结论**：侧栏树 `分组 → 片段`，点片段插入；命令为
`插入片段` / `把选中文字存为片段` / `删除片段` / `恢复上次删除的片段` /
`导出全部片段到光标处` / `从选中内容导入片段`。
**理由**：插件**没有输入 UI**（`qing.ui` 只有 `toast`，没有 prompt / 对话框），
"给片段起名字"只能从已有内容推导：名字取选区首行的纯文本（剥掉 `#`、`-`、`>`、`1.` 等标记，截 30 字符）。
树的交互面因此是唯一不需要输入框的入口。

### D4 分组只能是内置三组 + 「未分组」

**结论**：首装播种 `写作` / `会议` / `待办` 三个分组；新片段默认进 `未分组`；
**点分组行 = 在该分组里新建片段**（`commands.register` 的 `handler(itemId)` 会收到行 id，
这是 `qing-outline` 已经验证过的机制，同一行既能展开也能触发命令）。
**理由**：自由创建分组需要输入分组名，同样卡在「没有输入 UI」。
这是本轮发现的**第三个宿主能力缺口**，记为待定的 `ui.input` 提案。

### D5 权限 6 条，备份改走编辑器文本而不是剪贴板

**结论**：`permissions = ["storage", "views", "notify", "editor:read", "editor:write", "editor:selection"]`。
导出 = 把 JSON（含 ```` ```json ```` 围栏）插入光标处；导入 = 读当前选区、剥围栏后解析。
**理由**：grill 中「备份走剪贴板 JSON」与「少要权限」互相冲突（剪贴板方案要
`clipboard:read` + `clipboard:write`）。二者取其一，选**权限更小**的那条：
导出走 `editor:write`、导入走 `editor:read`，两条都是已授权的路径，零新增权限。
代价是导出的 JSON 落在笔记里需要用户自己保存或复制——对"逃生舱"级别的备份够用。

> **1.0.0 在这里错过了 `notify`。** 当时把清单压成 5 条，漏了每条命令末尾都要调的
> `ui.toast`——见下面的「1.0.0 事故」。定权限时必须以代码里实际调用的方法为准，
> 逐条对照 `bridge.ts::REQUIREMENTS`，不能凭"我需要哪些能力"凭记忆列。

### D6 首装播种三条示例片段

**结论**：`写作/日期小标题`、`会议/会议纪要`、`待办/任务清单骨架`，用 `storage` 的 `seeded` 标记保证只播一次。
**理由**：空树 + 无输入 UI 会让首次打开的用户判定"插件坏了"。
`seeded` 独立于片段数据，所以用户删光后不会复活——这正是 `seeded` 而不是"数组为空就播种"的原因。

### D7 删除前整表快照，只保一份

**结论**：删除单条前把整个片段数组写进 `trash` 键（带时间戳），`恢复上次删除的片段` 覆盖式写回并清空 `trash`。
**理由**：不能弹确认框、`toast` 也不能带按钮，只能靠"可撤销"而不是"二次确认"——
二次确认要求用户记住上一次点了什么，快照不需要。

### D8 四条硬上限

| 项 | 上限 | 依据 |
| --- | --- | --- |
| 单条片段 `body` | 20,000 字符 | 防止一次粘贴把整篇笔记塞进片段 |
| 片段条目数 | 500 | 树的可枚举性 + 序列化体积 |
| 一次导出 | 200,000 字符 | `replace` 硬限是 1,000,000，但 1MB 文本塞进编辑器会明显卡顿 |
| 序列化后总量 | 900,000 字符 | `storage` 配额 1 MB，留 10% 余量后主动拒绝并提示，好过让宿主抛 `E_QUOTA_EXCEEDED` |

## 1.0.0 事故：少一条 `notify`，所有命令静默失败

**现象**（真机，2026-10-28 23:13）：插件装得上、授权对话框只列 5 条、侧栏面板三组正常、
种子数据也写进了 `storage.json`——但点任何命令都没反应。插件详情页错误日志里 7 条
`E_PERMISSION_DENIED`，间隔 1–3 秒，正好对应点击次数。

**根因**：清单漏了 `notify`，而每条命令的最后一步都是 `ui.toast(...)`。
`bridge.ts::REQUIREMENTS` 里 `ui: { toast: "notify" }`，未授权即拒绝。
面板渲染和种子写入只走 `views` / `storage`，所以"看起来一切正常"——
这是最坏的失败形态：**功能全对，用户只看到"没反应"**。

**为什么门禁没抓住**：`verify-plugin-snippet.mjs` 的 mock `qing` 对任何调用都点头，
清单缺权限也照样 43 条全绿。它验证的是逻辑，不是权限面。

**修复**：
1. 清单补 `notify`，版本升 **1.0.1**（1.0.0 已发布，按规则不复用版本号）
2. 门禁加**权限闸门**：mock 按清单的 `permissions` 逐方法校验，表来自 `bridge.ts::REQUIREMENTS`；
   任何未授权调用直接抛 `E_PERMISSION_DENIED`，并在结尾断言"全程没有权限拒绝"
3. 反证：把 `notify` 从清单临时移掉后，9 条断言立刻红在
   `FAIL qing.snippet.insert 抛异常：E_PERMISSION_DENIED: notify`；恢复后 44 条全绿

**教训**：`apiVersion: 1` 里 `toast` 不是免费能力。写清单时逐条过 REQUIREMENTS 表，
比"我要读笔记、要写编辑器"这种按意图列法可靠。

## 待定问题

1. ~~**上架市场**~~ —— 已于 2026-10-28 完成，见下节。
2. **`ui.input` 提案**：没有它，分组与重命名永远只能靠内容推导。若要加，属于宿主 API 变更
   （`apiVersion` 2 + 6 处权限同步点），不是插件侧能解决的。
3. **片段自动展开**（输入 `[[片段名]]` 就地展开）：需要编辑器内容变更事件，`apiVersion: 1` 只有
   `activate` / `deactivate`，只能命令式触发。

## 上架记录（2026-10-28）

两次提交、一次推送，`Qing-Notepad-Plugins` 的 `main` 两个远端同步到 `cdf7c10`：

| 提交 | 内容 | 为什么分开 |
| --- | --- | --- |
| `81e13dc` | 包 `qing.snippet-1.0.0.qnp` + 校验器权限白名单 8→13 | `download` 必须钉**包含该包字节**的 commit SHA，而 SHA 在提交前不可知 |
| `cdf7c10` | `index.json` 加条目（`download` 指向 `81e13dc`）+ README | 第二次提交才能引用第一次的 SHA |

**发现并修掉的阻塞点**：市场校验器 `scripts/validate-index.mjs` 的 `KNOWN_PERMISSIONS`
停在 P1a 之前的 8 个码，客户端已有 13 个。后果不是报错，而是**任何用 `editor:*` / `views`
的插件都过不了校验器、永远上不了架**——`qing.outline` 上不去就是这个原因，不是"没来得及"。
这处白名单在另一个仓库，属于第 7 个同步点，已补进 `plugin-guide.md` §2.2。
