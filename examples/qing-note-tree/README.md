# 笔记树结构图（`qing.note-tree`）

把笔记目录画成 canvas 上的树：文件夹是分支、笔记是叶子，连线是曲线。模仿幕布的「大纲 → 导图」形态，但数据源是本机的笔记库。

## 用法

1. 打开画布视图，切到（或新建）一张要承载结构图的画布。
2. 命令面板执行 **「把笔记树画到当前画布」**。
3. 展开阅读：双击笔记节点会打开对应的笔记；文件夹与根节点不可双击。

另外两条命令：

| 命令 | 作用 |
| --- | --- |
| 为缺失摘要的节点生成 AI 概括 | 对**还没有摘要**的笔记调用你自己的 AI 接口，一次最多 8 篇，结果按内容 hash 缓存 |
| 清理源笔记已删除的节点 | 对比画布上的引用与当前笔记库，删掉源已经不存在的节点及其连线 |

## 权限

| 权限 | 为什么需要 |
| --- | --- |
| `notes:read` | 读文件夹树与笔记标题（`notes.tree()`）与正文（`notes.get()`，用于生成摘要片段） |
| `canvas:read` | 只读取画布上引用节点的标识，用来判断哪些节点已被删除 |
| `canvas:write` | 写入引用节点与连线 |
| `ai:summarize` | 调你的 AI 接口生成概括，**消耗你的额度**，只在你点命令时发生 |
| `storage` | 存摘要缓存（按内容 hash） |
| `notify` | 报告结果 |

插件拿不到画布条目的 id，也拿不到你画的其它内容：它用 `note:<id>` / `folder:<id>` / `root` 这样的引用键与宿主交互。

## 重新拉取 = 同步，不是重建

节点按引用键 upsert：**已存在的节点保留你拖到的位置**，只更新标题、摘要片段与 AI 概括。所以拉过一次之后可以随意调整布局，再拉不会被冲掉。

「文件树」是结构性视图：重命名会跟随，移动文件夹会在下次拉取时补一条新连线（旧连线不会自动消失，需手动删）。

## 规模

- 超过 **150** 个笔记节点时降级：每个文件夹最多画 12 篇，其余在提示里报「省略 N 篇」。
- 抽屉式的折叠交互这一版没有实现：宿主没有「插件响应节点点击」的通道，折叠会做成一个点了没反应的控件，不如不做。

## 开发

```bash
npm run typecheck
npm run build      # esbuild → dist/extension.js
npm run pack       # 需要 PowerShell 的 Compress-Archive；本仓库当前环境用 python zipfile 打包
```

逻辑门禁：仓库根 `npm run verify:plugin-note-tree`（30 项断言，mock 宿主跑 bundle）。

## 已知边界

- **不做反向回写**：节点是只读引用，画布上改不了笔记正文。这是刻意取舍——它同时消掉了双向同步的整类冲突。
- **不做自动墓碑**：你在画布上删掉的节点，再拉一次会重新出现。想彻底去掉，请删源笔记后跑「清理失效节点」。
- 折叠、多布局（上下图 / 居中图）未实现，v1 只有右向树。
